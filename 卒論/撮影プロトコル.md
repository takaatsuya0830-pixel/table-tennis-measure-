# 卓球ボール計測 撮影プロトコル（精度向上のための再撮影手順）

2026-06-09 作成。既存データの解析で判明した精度の律速要因を踏まえ、再撮影時の推奨設定をまとめる。
背景・根拠は解析メモ参照（回転rpsの俯瞰投影問題、fps=240の確定、キャリブレーション不一致など）。

---

## 0. 全体共通

| 項目 | 推奨 | 理由 |
|---|---|---|
| 実効fps | **240 fps**（Pixel 9a スロー、`com.android.capture.fps`で確認済み） | 旧コードの233は誤り。解析fpsと一致させる |
| 解像度 | 1920×1080 以上 | ボールを大きく写すため |
| ブレ対策 | **明るい均一拡散光**で短露光 | モーションブラーが回転・速度の最大の敵 |
| 床 | 平坦・均一・無地に近い面 | 検出の誤検出（木目・継ぎ目）を減らす |
| 余計な物 | **画面内に明るい固定物を置かない** | 旧回転動画はHoughが右端の固定物に張り付いて全滅した |
| 試行数 | **各条件5試行以上** | 統計的信頼性（平均±SD） |
| キャリブレーション | 後述の二重校正（ルーラー＋ボール径） | 校正がμr誤差の主因と判明 |

## 1. 回転速度(rps)用 — ★横アングルが必須

俯瞰では単一黒点のatan2が幾何学的に破綻する（黒点が半回転ごとに隠れ、投影が非線形で
回転速度を過大評価する）。実際、既存俯瞰データでは黒点rps≈17に対し、すべりなし転がりから
求めた信頼値は≈10で、約1.7倍も食い違った。

### セットアップ
- **カメラを床と同じ高さ**に置き、光軸を水平にする。
- 光軸を**ボールの転がり方向に対して垂直**に向ける（真横から見る）。
  → 回転軸がカメラを向き、黒点が画面内で**真円**を描く。atan2角＝回転角が**線形**になる。
- ボールが**画面いっぱい**に近くなるよう近づく/ズーム（**ボール半径 80〜150px** 目標）。
  小さいと黒点の重心がぶれる。

### マーカー
- **小さく高コントラストな点**を1つ（白球に黒の小円）。
  大きすぎるマーカーは前縮みで重心がぶれる（既存動画の失敗）。
- できれば**90°ずらして2点**、または極を通る細線を描くと、片方が隠れても追える。

### 動かし方
- ボールを**ゆっくり**転がす（1回転あたりのフレーム数を稼ぐ）。
  - 目安: 240fpsで1回転に最低10〜20フレーム欲しい → 回転は概ね **< 12〜24 rps** に。
  - ナイキスト限界は 120 rps だが、余裕をもって低速で。
- ボールが**画面内に長く留まる**軌道に（横切るのが速すぎると数フレームで消える＝既存の失敗）。
- まっすぐ転がし、奥行き方向の移動を抑える（ピント・スケール一定に）。

### 照明
- 明るい均一拡散光で**短露光**。既存動画の青み・縁の影・ブラーを解消。
- 黒点が「真っ黒(輝度≲40)」に写るくらいコントラストを確保（検出の絶対暗度ゲートが効く）。

## 2. 速度・転がり摩擦係数(μr)用

μrの精度は、位置の放物線フィット化で**フィット誤差は1.6%まで低減済み**。
残る主因は**キャリブレーション（px/cm）**なので、ここを堅牢にするのが最重要。

### セットアップ
- カメラ光軸を計測面に**垂直**、ボール軌道を画面**中央**に通す
  （周辺ほどパースでpx/cmが変化するのを避ける）。
- ボールを画像の**水平/垂直軸と平行**にまっすぐ転がす。
- **転がり開始〜停止の全区間が画面に収まる**ようにする（窓を長く取れる）。

### キャリブレーション（二重化）
1. **ルーラー/メジャー**を床（＝転がり面）に置いて一緒に写し、既知長（例:30cm）のpx数を測る。
   - 重要: ルーラーは**ボール中心の高さ(=半径2cm)ではなく床**にある。カメラが遠ければ差は1〜2%だが、
     近接撮影では無視できない。できるだけ**カメラを遠く**して正射影に近づけるか、
     ボール中心高さに合わせた基準を置く。
2. **ボール直径基準**: 既知直径40mmと検出直径pxから px/cm を別途算出。
3. 2つが**一致するか確認**（既存データは31.3 vs 22.5で28%も食い違い、これがμr 0.08 vs 0.11の差を生んだ）。
   一致しなければセットアップを見直す。
- さらに堅牢にするなら**チェッカーボード**を一度写してカメラ校正（パース・歪み補正）。

### 動かし方
- 初速がばらつくと一部試行が外れ値になる（旧Trial4,5が初速異常で除外）。
  ある程度そろえて5試行以上。

## 3. 撮影後の解析フロー（このリポジトリ）

1. `convert_hevc.py` でH.264化（必要なら）。
2. 回転: `detect_spin.py` または `spin_salvage.py`（横アングルなら窓長・R²が大幅改善するはず）。
3. 速度→μr: `detect_ball.py` → `fit_mu_position.py`（位置放物線フィット、推奨）。
   - `fit_mu_position.py` は px/cm を指定すればルーラー値とボール自己校正値の**両方でμrを出し**、
     校正感度を表示する。
4. 回転の裏取り: `spin_from_rolling.py` で v/(2πr) と黒点rpsを比較。
   横アングルで撮れていれば両者が一致するはず（すべりなし転がりの実証）。
